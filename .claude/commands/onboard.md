Configure and set up this project brain. Asks you for each config value, writes `project.config.yaml`, replaces all placeholders in the vault, and creates your first SOW directory.

Run this once from the repo root before moving into the vault.

---

## Step 1 — Check existing config

Read `project.config.yaml` if it exists.

- If it exists and has real values (not defaults), show a summary of the current config and ask:
  > "A config already exists. Update it, or proceed with current values?
  > (u) Update — I'll ask you each field again
  > (p) Proceed — apply the existing config as-is"
  If the user chooses proceed, jump to Step 3.

- If it doesn't exist, continue to Step 2.

---

## Step 2 — Collect config values

Ask each field below in order, one at a time. For every field:
- Show the field name and a one-line explanation
- Show the example value in parentheses
- Wait for the user's answer before moving to the next field
- If the user hits enter with no input on an optional field, leave it empty

**Required fields:**

1. **PROJECT_NAME**
   > "What's the short client or product name? This is used to filter meeting notes and label the vault.
   > (e.g. `ZenQMS`, `CloudSort`)"

2. **CLIENT_NAME**
   > "Full legal or formal client name — used in documents and the SOW reference.
   > (e.g. `ZenQMS Inc.`) — press enter to use PROJECT_NAME"
   If skipped, use the PROJECT_NAME value.

3. **ENGAGEMENT_TYPE**
   > "What type of engagement is this?
   > (e.g. `GenAI Assessment`, `Staff Augmentation`, `POC`, `Implementation`)"

4. **ENGAGEMENT_CONTEXT**
   > "One or two sentences describing what Loka is doing for this client.
   > (e.g. `Loka is building a RAG-based document search system for ZenQMS's compliance team.`)"

5. **OWNER_NAME**
   > "Your full name — you're the brain owner for this engagement."

6. **OWNER_HANDLE**
   > "Your @handle used in notes and attributions.
   > (e.g. `@bruno`)"

7. **OWNER_ROLE**
   > "Your role on this engagement.
   > (e.g. `TPM`, `ML Lead`, `Tech Lead`)"

8. **FIRST_SOW**
   > "What SOW are you starting with? This becomes the directory name under `sows/`.
   > (e.g. `sow1`, `sow2`, `phase1`) — ask if unsure: most engagements start with `sow1`"

9. **GEMINI_NOTES_FOLDER**
   > "Google Drive folder URL where your Gemini meeting notes live. Open the folder in Drive and paste the URL.
   > (e.g. `https://drive.google.com/drive/folders/abc123`)
   > Press enter to skip — you can set this later."

**Optional fields** (press enter to skip any of these):

10. **SOW_DOC_URL**
    > "Direct link to the SOW / Scope of Work document in Google Drive.
    > If you skip this, /bootstrap will search your Drive folder automatically.
    > Press enter to skip."

11. **SLACK_CHANNELS**
    > "Slack channel(s) for this project, comma-separated with # prefix.
    > (e.g. `#zenqms-general, #zenqms-tech`)
    > Press enter to skip."

12. **GEMINI_NOTES_DOCS**
    > "Specific Gemini note doc URLs, comma-separated — only needed if your notes aren't all in one folder.
    > Press enter to skip."

---

## Step 3 — Write project.config.yaml

Write `project.config.yaml` with the collected values. Use this exact format:

```yaml
# Project Brain Configuration
# Generated by /onboard — edit this file directly to update values.

PROJECT_NAME: "<value>"
CLIENT_NAME: "<value>"
ENGAGEMENT_TYPE: "<value>"
ENGAGEMENT_CONTEXT: "<value>"
OWNER_NAME: "<value>"
OWNER_HANDLE: "<value>"
OWNER_ROLE: "<value>"
FIRST_SOW: "<value>"
GEMINI_NOTES_FOLDER: "<value>"
SOW_DOC_URL: "<value>"
SLACK_CHANNELS: "<value>"
GEMINI_NOTES_DOCS: "<value>"
```

For any field the user skipped, write an empty string `""`.

Confirm: "Config written to project.config.yaml."

---

## Step 4 — Replace placeholders in the vault

Run this for each key/value pair where the value is not empty:

```bash
find project-vault -name "*.md" -print0 | xargs -0 sed -i "s|{{KEY}}|VALUE|g"
```

Process all 12 fields. Skip any field with an empty value (don't replace with empty string — leave the placeholder intact so the user knows it's unset).

After all replacements, verify no placeholders remain for the non-empty fields:

```bash
grep -r "{{KEY}}" project-vault --include="*.md" -l
```

If any non-empty field's placeholder is still found, report it as a warning.

Report: "Placeholders replaced across the vault."

---

## Step 5 — Create the first SOW directory

```bash
cp -r project-vault/sows/_template project-vault/sows/<FIRST_SOW>
mv project-vault/sows/<FIRST_SOW>/sow-reference.md project-vault/sows/<FIRST_SOW>/<FIRST_SOW>-reference.md
```

If `project-vault/sows/<FIRST_SOW>` already exists, skip and note: "sows/<FIRST_SOW>/ already exists — skipped."

Report: "Created sows/<FIRST_SOW>/."

---

Print:

If any fields were skipped, list them:

