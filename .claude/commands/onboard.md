Configure and set up this project brain. Asks you for each config value, writes `project.config.yaml`, replaces all placeholders in the vault, and creates your SOW directories.

Run this once from the repo root before moving into the vault.

---

## Step 1 — Check existing config

Read `project.config.yaml` if it exists.

- If it exists and has real values (not defaults), show a summary of the current config and ask:
  > "A config already exists. Update it, or proceed with current values?
  > (u) Update — I'll ask you each field again
  > (p) Proceed — apply the existing config as-is"
  If the user chooses proceed, jump to Step 3.

- If it doesn't exist, continue to Step 2.

---

## Step 2 — Collect global config values

Ask each field below in order, one at a time. For every field:
- Show the field name and a one-line explanation
- Show the example value in parentheses
- Wait for the user's answer before moving to the next field

1. **PROJECT_NAME**
   > "What's the short client or product name? This is used to filter meeting notes and label the vault.
   > (e.g. `ZenQMS`, `CloudSort`)"

2. **CLIENT_NAME**
   > "Full legal or formal client name — used in documents and the SOW reference.
   > (e.g. `ZenQMS Inc.`) — press enter to use PROJECT_NAME"
   If skipped, use the PROJECT_NAME value.

3. **ENGAGEMENT_TYPE**
   > "What type of engagement is this?
   > (e.g. `GenAI Assessment`, `Staff Augmentation`, `POC`, `Implementation`)"

4. **ENGAGEMENT_CONTEXT**
   > "One or two sentences describing what Loka is doing for this client.
   > (e.g. `Loka is building a RAG-based document search system for ZenQMS's compliance team.`)"

5. **OWNER_NAME**
   > "Your full name — you're the brain owner for this engagement."

6. **OWNER_HANDLE**
   > "Your @handle used in notes and attributions.
   > (e.g. `@bruno`)"

7. **OWNER_ROLE**
   > "Your role on this engagement.
   > (e.g. `TPM`, `ML Lead`, `Tech Lead`)"

---

## Step 3 — Write project.config.yaml

Write `project.config.yaml` with the collected values:

```yaml
# Project Brain Global Configuration
# Generated by /onboard — edit this file directly to update values.

PROJECT_NAME: "<value>"
CLIENT_NAME: "<value>"
ENGAGEMENT_TYPE: "<value>"
ENGAGEMENT_CONTEXT: "<value>"
OWNER_NAME: "<value>"
OWNER_HANDLE: "<value>"
OWNER_ROLE: "<value>"
```

Confirm: "Config written to project.config.yaml."

---

## Step 4 — Replace placeholders in the vault

Run this for each of the 7 fields where the value is not empty:

```bash
find project-vault -name "*.md" -print0 | xargs -0 sed -i "s|{{KEY}}|VALUE|g"
```

Skip any field with an empty value — leave the placeholder intact so the user knows it's unset.

After all replacements, verify no placeholders remain for the non-empty fields:

```bash
grep -r "{{KEY}}" project-vault --include="*.md" -l
```

If any non-empty field's placeholder is still found, report it as a warning.

Report: "Placeholders replaced across the vault."

---

## Step 5 — Set up SOWs

Ask:
> "Which SOWs do you want to set up? List them comma-separated.
> Starting fresh on SOW1? Just type `sow1`.
> Joining mid-project? List prior SOWs too so bootstrap can load their history.
> (e.g. `sow5, sow6, sow7` or just `sow1`)"

For each SOW in the list (in order):

**5a — Create the SOW directory:**

```bash
cp -r project-vault/sows/_template project-vault/sows/<sow>
mv project-vault/sows/<sow>/sow-reference.md project-vault/sows/<sow>/<sow>-reference.md
```

If `project-vault/sows/<sow>` already exists, skip the copy and note it.

**5b — Collect per-SOW config** (ask each field, press enter to skip optional ones):

1. **DRIVE_FOLDER** (required — press enter to skip and fill in later)
   > "Google Drive folder URL for [sow] meeting notes.
   > Open the folder in Drive and paste the URL.
   > (e.g. `https://drive.google.com/drive/folders/abc123`)"

2. **SOW_DOC_URL** (optional)
   > "Direct link to the SOW / Scope of Work document for [sow] in Google Drive.
   > If you skip this, /bootstrap will search the Drive folder automatically.
   > Press enter to skip."

3. **SLACK_CHANNELS** (optional)
   > "Slack channel(s) for [sow], comma-separated with # prefix.
   > (e.g. `#client-sow7-general, #client-sow7-dev`)
   > Press enter to skip."

4. **GEMINI_NOTES_DOCS** (optional)
   > "Specific Gemini note doc URLs for [sow], comma-separated.
   > Only needed if notes aren't all in one folder.
   > Press enter to skip."

**5c — Write `project-vault/sows/<sow>/sow.config.yaml`:**

```yaml
# SOW Configuration — <sow>
# Created by /onboard — edit directly to update.

DRIVE_FOLDER: "<value or empty>"
SOW_DOC_URL: "<value or empty>"
SLACK_CHANNELS: "<value or empty>"
GEMINI_NOTES_DOCS: "<value or empty>"
```

Report: "Configured sows/<sow>/."

Repeat 5a–5c for every SOW in the list.

---

Print:

```

```
