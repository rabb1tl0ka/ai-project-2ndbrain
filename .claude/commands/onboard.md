Configure and set up this engagement brain. Collects the three global config values, writes `config.yaml`, replaces placeholders in the vault, and creates your SOW directories.

Run this once from the repo root before anything else.

---

## Step 1 — Check existing config

Read `config.yaml` if it exists.

- If it exists and has real values (no placeholder defaults), show a summary and ask:
  > "A config already exists. Update it, or proceed with current values?
  > (u) Update — I'll ask you each field again
  > (p) Proceed — apply the existing config as-is
  > (s) Skip —  skip creating the config"

  If the user chooses proceed, jump to Step 3.
  If the user choose to skip, jump to Step 5.

- If it doesn't exist, continue to Step 2.

---

## Step 2 — Collect global config values

Ask each field below in order, one at a time. Show the field name, a one-line explanation, and an example. Wait for the answer before moving on.

1. **CLIENT_NAME**
   > "Full client name — used across the vault in documents and templates.
   > (e.g. `ZenQMS Inc.`, `ACME Corp.`)"

2. **OWNER_NAME**
   > "Your full name — you're the engagement brain owner. You forked this repo, you manage the PRs.
   > (e.g. `Bruno Costa`)"

3. **OWNER_ROLE**
   > "Your role on this engagement.
   > (e.g. `TPM`, `ML Lead`, `Tech Lead`)"

---

## Step 3 — Write config.yaml

Write `config.yaml` at the repo root with the collected values:

```yaml
# Engagement Brain — Global Config
# Generated by /onboard — edit directly to update values.

CLIENT_NAME: "<value>"
OWNER_NAME: "<value>"
OWNER_ROLE: "<value>"
```

Confirm: "Config written to config.yaml."

---

## Step 4 — Replace placeholders in the vault

Run this for each of the 3 fields where the value is not empty:

```bash
find . -path ./.kernel -prune -o -name "*.md" -print0 | xargs -0 sed -i "s|{{KEY}}|VALUE|g"
```

Skip `README.md` at the root (it's user-facing docs, not a vault file).

After all replacements, verify no placeholders remain for the non-empty fields:

```bash
grep -r "{{KEY}}" . --include="*.md" --exclude-dir=.kernel -l
```

If any non-empty field's placeholder is still found, report it as a warning.

Report: "Placeholders replaced across the vault."

---

## Step 5 — Set up SOWs

Ask:
> "Which SOWs do you want to set up? List them comma-separated.
> Starting fresh? Just type `sow1`.
> Joining mid-project? List prior SOWs too so bootstrap can load their history.
> (e.g. `sow5, sow6` or just `sow1`)"

For each SOW in the list (in order):

**5a — Create the SOW directory:**

```bash
cp -r sows/_template sows/<sow>
mv sows/<sow>/sow-reference.md sows/<sow>/<sow>-reference.md
```

If `sows/<sow>` already exists, skip the copy and note it.

**5b — Collect per-SOW config** (ask each field, press enter to skip optional ones):

1. **ENGAGEMENT_TYPE** (optional)
   > "What type of engagement is this SOW?
   > (e.g. `GenAI Assessment`, `POC`, `Staff Augmentation`, `Implementation`)
   > Press enter to skip."

2. **ENGAGEMENT_CONTEXT** (optional)
   > "One or two sentences: what is Loka building or delivering for this client under this SOW?
   > (e.g. `Loka is building a RAG-based document search system for ZenQMS's compliance team.`)
   > Press enter to skip."

3. **DRIVE_FOLDERS** (required — press enter to skip and fill in later)
   > "Google Drive folder URL(s) for [sow] meeting notes — comma-separated if you have multiple (e.g. separate folders for client and internal calls).
   > Open each folder in Drive and paste the URL(s).
   > (e.g. `https://drive.google.com/drive/folders/abc123, https://drive.google.com/drive/folders/xyz456`)"

4. **MEETING_FILTER** (optional — only needed if any folder is shared, like Meet Recordings)
   > "Are any of these folders shared (e.g. My Drive > Meet Recordings with mixed projects)?
   > If so, paste the string that identifies this project's meetings in the filename.
   > (e.g. `ZenQMS`, `ZenQMS SOW4`, `CS `) — press enter to skip if all folders are already SOW-specific."

6. **SOW_DOC_URL** (optional)
   > "Direct link to the SOW / Scope of Work document in Google Drive.
   > If you skip this, /bootstrap will search the Drive folder automatically.
   > Press enter to skip."

7. **SLACK_CHANNELS** (optional)
   > "Slack channel(s) for [sow], comma-separated with # prefix.
   > (e.g. `#client-sow1-general, #client-sow1-dev`)
   > Press enter to skip."

8. **GEMINI_NOTES_DOCS** (optional)
   > "Specific Gemini note doc URLs for [sow], comma-separated.
   > Only needed if notes aren't all in one folder.
   > Press enter to skip."

9. **sow_lead** (required)
   > "Who is the lead for [sow]? This is the person responsible for delivery — they'll have merge authority on the `[sow]` branch.
   > (e.g. `ronny`, `bruno`) — lowercase, first name is fine."

**5c — Write `sows/<sow>/sow.config.yaml`:**

```yaml
# SOW Configuration — <sow>
# Created by /onboard — edit directly to update.

ENGAGEMENT_TYPE: "<value or empty>"
ENGAGEMENT_CONTEXT: "<value or empty>"
DRIVE_FOLDERS: "<value or empty>"
MEETING_FILTER: "<value or empty>"
SOW_DOC_URL: "<value or empty>"
SLACK_CHANNELS: "<value or empty>"
GEMINI_NOTES_DOCS: "<value or empty>"
sow_lead: "<value or empty>"
```

Report: "Configured sows/<sow>/."

**5d — Create the long-lived SOW branch:**

Check if the branch already exists on origin:
```bash
git ls-remote --heads origin <sow>
```

If it does NOT exist:
```bash
git checkout -b <sow>
git push -u origin <sow>
git checkout -
```

Print:
```
✓ Branch `<sow>` created and pushed to origin.
  Team members should branch off `<sow>` and PR back into it.
  You PR `<sow>` → `main` periodically to sync with the rest of the engagement.
```

Then print a suggestion:
```
💡 Consider protecting `<sow>` on GitHub to require PRs from team members
   (Settings → Branches → Add ruleset). Recommended setup:
   - Require PRs to merge into `<sow>`
   - Add yourself (<sow_lead>) as a bypass actor so you can push/merge
     directly for chores without needing a reviewer
   This keeps the team's contributions visible while not blocking you on
   markdown updates and day-to-day maintenance.
```

If the branch already exists:
```
✓ Branch `<sow>` already exists on origin — skipped creation.
```

Repeat 5a–5d for every SOW in the list.

---

## Step 6 — Wrap up

Print:

```
Onboarding complete.

✓  config.yaml written
✓  Vault placeholders replaced
✓  SOWs created: <list>
✓  Branches created on origin: <list of sow branches created, or "none — all already existed">

Next: run /bootstrap to load the brain with real project data
(SOW documents, meeting notes, Slack history — for all SOWs).
```

If any per-SOW fields were skipped, list them:

```
⚠  These SOW config fields were left empty — fill them in before running /bootstrap:
   - sows/<sow>/sow.config.yaml → DRIVE_FOLDERS
```
